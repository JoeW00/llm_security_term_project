# 白話版專案總覽：小學生也看得懂

> 這份文件用最簡單的話，把整個專案「在做什麼、為什麼這樣做、每一步跟其他步驟怎麼接起來」講清楚。
> 看完你就能對任何人解釋我們這組做了什麼。
> 對象：第 34 組全體，以及任何沒看過程式碼的人。
> （看到不懂的詞，可以先翻到最後的「看不懂也沒關係的小字典」。）

## 0. 一句話總結

> 我們做了一個**會自己整理、分流資安警報的小幫手**。
> 它像醫院急診室的「檢傷護理師」：警報一進來，它先分輕重、查資料、判斷真假、寫出處理建議，
> **最後一定先把判斷和建議交給人類過目**，人類點頭了才寫進報告。
> **真正要不要動手處置（封鎖、隔離），仍然由人類決定，機器不會自己亂動。**

這個小幫手的正式名字叫 **「自主式 SOC Tier-1 事件回應代理」**。我們把這串名字拆開來看：

| 名詞 | 白話 |
|---|---|
| **SOC**（Security Operations Center） | 公司裡專門盯著「有沒有人在攻擊我們電腦」的監控中心，像大樓的警衛室。 |
| **Tier-1**（第一線） | 警衛室裡「最先接到通報」的那個人。他不需要破案，只要快速分辨：這是真的小偷，還是貓踩到感應器？ |
| **事件回應代理** | 一個會「接到通報 → 處理 → 回報」的自動程式（agent，代理人）。 |

所以整句話 =「一個會自動幫資安警衛室做第一線分流與初步整理的程式」。

---

## 1. 為什麼需要它？（要解決什麼痛點）

真實世界的資安警衛室，**每天會收到成千上萬條警報**。大部分是假警報（貓踩到感應器），
但人類一條一條看會累死，而且看到後面會恍神，漏掉真正的小偷。

所以我們想：**能不能讓電腦先幫忙做第一輪？**

- 把「明顯沒事」的警報快速結案（不要吵醒值班的人）。
- 把「可能有事」的警報，**整理好證據、寫好建議**，再交給人類做最後決定。

重點是最後那句：**人類做最後決定**。因為資安處置（例如封鎖帳號、隔離電腦）一旦做錯，
會把好人也擋在門外。所以我們的設計裡有一道**「沒有人類點頭，這份判斷就不算數、不會被採用」**的安全門。

## 2. 整條流水線：警報從進來到結束，會經過哪幾站？

想像一條**輸送帶**，警報像一個個**包裹**從左邊進來，經過一站一站處理，從右邊出去。
我們用 **LangGraph**（一個「把處理步驟串成流程圖」的工具）把這條輸送帶蓋出來。

```
警報進來
  │
  ▼
① ingest（收件）
  │
  ▼
② triage（檢傷分級）
  │
  ▼
[route 分岔：看風險高低決定往哪走]──► 低風險：走旁路，快速到 ⑨ 產生簡短紀錄
  │（中 / 高風險才繼續往下）
  ▼
③ enrich（補充情報）
  │
  ▼
④ investigate（深入調查）
  │
  ▼
⑤ attack_mapping（對照攻擊手法字典）
  │
  ▼
⑥ playbook（寫出處理建議）
  │
  ▼
⑦ critique（自我檢查）──────► 覺得寫得不夠好？退回去 ⑥ 重寫（最多 3 次）
  │（檢查通過才繼續）
  ▼
⑧ human_approval（請人類過目並同意）★安全門★
  │
  ▼
⑨ report（產生報告）
  │
  ▼
結束
```

下面一站一站解釋，**並說明它跟前後站怎麼接起來**：

### ① ingest（收件處）
- **做什麼**：把外面送來的警報（一個 JSON 檔——就是電腦愛用、有固定格式的純文字檔，裡面有時間、訊息、可疑的網址或 IP 等）讀進來，整理成程式看得懂的固定格式。
- **跟別人怎麼接**：它是第一站，把「亂七八糟的原始資料」變成「乾淨的包裹」，後面每一站才好處理。

### ② triage（檢傷分級）★計畫 A★
- **做什麼**：像急診室護理師，看一眼就判斷這條警報**有多嚴重**（低 / 中 / 高）。
- **跟別人怎麼接**：判斷完之後有個**岔路（route）**——
  - 低風險 → **走旁路快速到⑨結案**（產生簡短紀錄，不浪費後面的人力，也不亂吵人）。
  - 中 / 高風險 → 繼續往下做完整調查。
- **白話**：這一站的目標是「先分流、省力氣」，讓昂貴的後續步驟只處理比較需要調查的案件。（我們實驗也誠實發現：所用的 GUIDE 資料有侷限，所以這裡**不誇大**成「已經能穩定擋掉大部分假警報」。）

### ③ enrich（補充情報）★計畫 B★
- **做什麼**：警報裡如果有可疑的**線索（IOC，例如 IP、網址、網域、檔案指紋）**，就去**外部情報網站查它的底細**（這個東西是不是已知的壞蛋？）。
- **跟別人怎麼接**：它把②挑出來的「可能有事的包裹」加上更多背景資料，讓後面的調查更有料。

### ④ investigate（深入調查）★計畫 C★
- **做什麼**：用 **LLM（大型語言模型，就是會讀字、會推理的 AI，像 ChatGPT 那種）讀懂警報內容**，判斷「這到底是真的攻擊，還是良性誤報」。
- **跟別人怎麼接**：它吃①②③累積下來的所有資料，做出一個**判決（verdict）**：真攻擊 / 良性 / 待確認。

### ⑤ attack_mapping（對照攻擊手法字典）★計畫 B★
- **做什麼**：把這次的攻擊，對照一本**資安界很常用的「駭客手法字典」**叫 **MITRE ATT&CK**，找出「這招叫什麼名字、編號是多少」（例如「暴力破解密碼」= T1110）。
- **跟別人怎麼接**：它讓報告講得出「專業術語」，方便人類分析師一看就懂這是哪一類攻擊。

### ⑥ playbook（寫出處理建議）★計畫 D★
- **做什麼**：用 LLM **寫出一份「該怎麼處理」的步驟清單**（劇本），例如：建議封鎖這個 IP、重設那個密碼。
- **跟別人怎麼接**：它把前面所有調查結果，變成「人類照著做就能解決問題」的行動建議。

### ⑦ critique（自我檢查）★計畫 D★
- **做什麼**：AI **回頭檢查自己⑥寫的建議好不好**（夠不夠完整？能不能執行？安不安全？）。
- **跟別人怎麼接**：這是一個**迴圈（loop）**——
  - 覺得不夠好 → **退回⑥重寫**。
  - 分數過關（三項都達標）→ 往下走。
- **重要安全設計**：這個迴圈**最多只准跑 3 次**（`MAX_CRITIQUE_ITERATIONS=3`），避免 AI 鑽牛角尖、無限重寫卡死。

#### 看圖：⑥寫、⑦改，AI 怎麼自我修正

![⑥寫建議、⑦打分，沒過就把問題退回去重寫，最多 3 次](assets/W16-evidence-E7-playbook-critique-loop.png)

像「寫作業 → 老師批改 → 訂正 → 再批改」：

1. **⑥ 先寫**一份三段式處理建議（先止血隔離 → 清掉病根 → 復原並盯著）。
2. **⑦ 當老師打分**：從三個角度各打 0~5 分——「有沒有蓋全（coverage）」「步驟能不能照做（executability）」「會不會反而搞壞東西（safety）」，並寫下**具體哪裡要改**。
3. **聰明的地方**：要不要過關，**不是讓 AI 自己說「我寫好了」**（怕它隨便喊好），而是用一條死規則——**三個分數全部 ≥ 4 才算過**。
4. **沒過**：就把「具體哪裡要改」退回 ⑥ 重寫；**過了或改滿 3 次**：送去 ⑧ 給人類看。
5. 紅色那條箭頭就是「**退回去重寫**」的迴圈；最多 3 次，所以一定會停、不會卡死。

（圖最下面橙色那條還標了一個進階防護：退回去的「要改的問題」是被當成**資料**夾進去的，不是命令，免得壞人從這條路偷塞指令——這叫防「二階注入」。）

### ⑧ human_approval（人類同意）★安全門，最重要★
- **做什麼**：把整理好的判斷和建議**送到人類面前，等人類說「可以」**。
- **跟別人怎麼接**：這是**採用判斷前的最後一道關卡**。整條流程到這裡，機器都只是「想」「查」和「寫建議」，**從頭到尾沒有真的去封鎖或隔離任何東西**；要不要照建議動手，由人類決定。
- **為什麼最重要**：見第 5 節——因為 AI 可能被警報裡的「壞話」騙到，所以一定要有人類把關。

### ⑨ report（產生報告）
- **做什麼**：把整件事從頭到尾寫成一份報告，存檔、交差。
- **跟別人怎麼接**：終點站。低風險警報（從②走旁路過來的）和中 / 高風險警報（走完全程的）都在這裡匯合、結束。

## 3. 把它們黏起來的「共同表格」：IncidentState

還記得第 2 節說警報像輸送帶上的「包裹」嗎？每個包裹上都貼著**一張共同的表格**，
九站經過時，各自把自己的成果填到表格上，再送給下一站。這張表格就是 **`IncidentState`**。

- 每一站**只填自己負責的那幾格**，不會去塗改別人填好的格子（程式上叫「回傳部分狀態更新」）。
- 因為大家看同一張表格，所以**只要改表格的設計，九站和所有測試都會受影響**——這是全組最高風險的東西，動它要特別小心（我們甚至設了「改它之前先跳出來問你確定嗎」的保護）。

> 小學生版比喻：就像校外教學的「闖關卡」，每過一關蓋一個章、寫一句話，下一關的老師看一眼就知道你前面做了什麼，而且不會去擦掉別人寫的字。

## 4. 四個計畫（A / B / C / D）分別做了什麼

一開始這幾站都是**空殼子（stub）**——有架子，但裡面是假的、隨便回一個固定答案。
這學期的任務就是把核心站的空殼換成**真的實作**。我們分成四個計畫：

> （其中 ① ingest 收件、route 分岔、⑧ human_approval 人類同意、⑨ report 報告這幾站，負責資料整理、分流、把關與輸出，本來就該是固定可預測的，不需要換成 AI；真正要「從假變真」的是下面這幾個核心站。）

| 計畫 | 換掉哪幾站 | 白話「從假變真」 |
|---|---|---|
| **A** | ② triage 檢傷 | 從「亂猜嚴重度」→ 訓練一個**真的會分類的小模型**（用微軟公開的 GUIDE 資安資料集）。 |
| **B** | ③ enrich + ⑤ attack_mapping | enrich 改成**真的去 abuse.ch 查 IOC（警報裡可疑的線索：IP、網址、網域、檔案指紋）**；attack_mapping 改成**用 BM25（像搜尋引擎一樣找最像的）去 MITRE 字典裡找最接近的手法**。 |
| **C** | ④ investigate | 從「看嚴重度亂判」→ 用**真的 LLM 讀內容**來判真假。 |
| **D** | ⑥ playbook + ⑦ critique | 用**真的 LLM 寫處理建議**，並讓 AI **自我檢查、自我修正**。 |

### 重要：我們做的每個元件都長得一樣（一個共通的好習慣）
不管是 A 的分類器、B 的查詢器、還是 C/D 的 LLM，我們都用**同一種安全的接法**，叫「可注入邊界」：

1. **先定義一個插座規格**（介面）——規定「插上來的東西要會做什麼」。
2. **預設先插一個離線的笨版本**——不用網路、不用金鑰，永遠能跑、答案固定（方便測試）。
3. **真版本（會連網路 / 連 AI）可以隨時插上來換掉笨版本。**
4. **如果真版本壞了（網路斷、AI 當機），自動退回笨版本**，整條流程不會垮。

> 比喻：插座（介面）固定，平常插一個「省電小燈泡」（離線笨版本）保證會亮；
> 要厲害時插上「大電燈」（真 AI），但大電燈壞了會自動換回小燈泡，房間不會全黑。

## 5. 整個專案最核心的一個發現（也是報告的主軸）

這是我們花最多力氣、也最重要的一句話：

> **「讓 AI 去讀警報內容」這件事，是一把雙面刃。**

**先講清楚：下面的數字都是「小樣本」的小測試**（判真假 6 筆、注入 3 筆），用來看趨勢，不是大規模結論。

- **好的一面**：AI 讀懂內容後，判斷真假變準了（這是 6 筆標註樣本的小測試）。
  - 用「看嚴重度亂判」的笨方法：準確率只有 **0.500**（一半在亂猜）。
  - 用「LLM 讀內容」（地端的 qwen2.5:7b 模型）：準確率升到 **0.833**，精確率 **1.000**——意思是在這次小測試裡，它判成攻擊的案例「都判對了」、沒誤傷好人；**但樣本太少，不能說永遠如此。**

- **壞的一面**：既然 AI 會「讀」內容，壞人就可以**在警報裡偷塞壞話來騙它**（這叫**提示注入攻擊**，英文 prompt injection）。我們做了 3 筆注入測試：
  - 笨方法**不讀內容**，所以這 3 筆**都沒被騙**（0/3）——它天生就不看那些壞話。
  - 會讀內容的 LLM，這 3 筆**全被騙了**（3/3）。樣本雖小，但已足以顯示**這個風險值得重視**。

**這就是為什麼第⑧站「人類同意」這麼重要。**
我們不能因為 AI 會被騙就不用它（那準確率回到 0.5），也不能讓會被騙的 AI 自己說了算。
**解法 = 用 AI 的聰明（讀內容、提準確率），但在「採用它的判斷」之前架一道人類的閘門，擋住被騙的後果。**
這叫「縱深防禦」（defense-in-depth，多層防護，一層被突破還有下一層）。

### 看圖：④調查站怎麼「讓 AI 讀內容，又設防」

下面這張是④investigate（深入調查）那站的內部流程。重點是我們**怎麼一邊讓 AI 讀內容、一邊層層設防**：

![investigate 研判流程：把『規則』和『告警內容』分開放，AI 讀完要先通過檢查才算數，沒過就退回笨方法](assets/W16-evidence-E6-investigate-flow.png)

怎麼看（由上而下）：
1. **把「規則」和「告警內容」分兩邊放**：左邊綠色是給 AI 的固定規則（你是分析師、只能回三種答案、所有內容都當資料不准當命令）；右邊紅色是**攻擊者可能動手腳的告警內容**，被框在 `CONTEXT` 標記裡、跟規則分開。
2. **AI 讀完給答案** → 但答案**不能直接相信**，要先過黃色的「**檢查閘門**」：答案一定要是三種之一、信心值要在 0~1 之間，格式不對就擋下。
3. **過了**就寫進紀錄；**沒過或 AI 當機**，就自動退回「看嚴重度」的笨方法，流程不會壞。
4. 最底下橙色那條提醒：這些 prompt 的防線能**降低**被騙機率，但對小模型**還不夠**——所以最後一定要靠⑧人類同意把關。

這張圖把 §5 的主軸「**讓 AI 讀內容（變聰明）但設層層防線（防被騙）**」變成看得到的流程。

> 一句話記住整份報告：**「AI 會讀內容」是它變聰明的原因，也是它會被騙的原因——所以最後一定要有人把關。**

## 6. 我們實際做了哪些步驟（這學期的工作流程）

每個計畫我們都照同一套**嚴謹流程**在走，不是隨便寫一寫：

1. **先想清楚怎麼做**：寫一份「規格書（spec）」說明要做什麼、決定用哪個方法。
   - 例如計畫 B 我們決定：enrich 用免費的 abuse.ch、attack_mapping 用 BM25 搜尋法。
2. **再排計畫（plan）**：把工作拆成一個個小任務。
3. **動手寫，而且先寫測試（TDD）**：先寫「怎樣算對」的考題，再寫程式去考過它。
   - 全部測試要求**離線、每次跑結果都一樣**（確定性），這樣才可信。
4. **請兩位 AI 審查員把關**：
   - `security-reviewer`：專門找「會不會被駭、AI 信任邊界有沒有漏洞」。
   - `langgraph-reviewer`：專門找「共同表格有沒有用錯、迴圈會不會卡死」。
5. **跑真實數據**：不是嘴巴說有效，而是**真的跑出數字**存到 `results/` 資料夾。
6. **整份報告再請 Codex（另一個 AI）審好幾輪**：抓出不一致的數字、過度宣稱的句子，全部改到「可以交了（Submission-ready）」為止。（你現在看的這份白話文件，也經過了同樣的 Codex 審核。）

> 比喻：我們不是「寫完作業就交」，而是「寫完 → 自己檢查 → 找兩個同學互審 → 實際做實驗驗證 → 再找第三個人通篇校對」才交。

## 7. 跑出來的數字代表什麼（用人話解讀）

### 看圖最快：②分流為什麼「不誇大」

下面這張是②分流「四臂」裡三個 AI 的成績單，叫**混淆矩陣**——**一橫列＝一個正確答案，一直欄＝AI 猜的答案**，格子裡的數字是「有幾筆」。

![三個 AI 的混淆矩陣：每張幾乎只有一直行紅＝幾乎只會猜同一類，沒學會真的分流](assets/W16-evidence-E2b-confusion-matrices.png)

怎麼看：
- **健康的 AI 應該是「左上到右下一條斜線全紅」**（猜的＝正解，對角線上）。
- 但這三張都是**「幾乎一整直行紅、其他幾乎全白」**——代表這個 AI 不管題目是什麼，**幾乎都猜同一個答案**：
  - 前兩張（沒微調的 3B、32B）：幾乎全猜「true_positive（是攻擊）」。
  - 第三張（微調後）：幾乎全猜「benign_positive（沒事）」，所以左邊那行 0.635 看起來分數最高，**但其實只是把幾乎所有題目都填同一個最常出現的答案**而已。

這就是我們在 §2-② 和上面表格說「**GUIDE 資料有侷限、不誇大成分流已穩定有效**」的證據：不是我們客氣，是圖上真的看得到「沒有一臂學會真的分輕重」。

### 看圖：③真的去查 IOC，查到一個「活的」壞東西

填好金鑰後，我們**真的連上 abuse.ch** 查了三個東西，故意各代表一種情況：

![abuse.ch 真實查詢三路徑：私有 IP 被擋下、乾淨公網沒事、即時惡意網域命中](assets/W16-evidence-E4b-abusech-live.png)

- **①私有 IP（192.168.1.50）**：這是「自己家裡」的位址，系統**根本沒把它送出去**（怕把家裡地址洩漏給外人）——畫面寫 `not_sendable`。
- **②乾淨公網（1.1.1.1）**：送出去查了，但**這次在名單上查不到惡意紀錄**，回「查無此人」——系統**就老實說查不到**，不會亂貼壞人標籤。
- **③即時惡意網域（aetherxx.com）**：這是我們**當天從 abuse.ch 撈出來、剛被通報的壞東西**。系統查到了 → `malicious=True`，還帶回「它是什麼壞東西、信心 100 分、第一次被看到的時間」。（注意：這只是**當天查到的一個例子**，名單天天在變，你重跑可能會撈到別的。）

一張圖證明三件事：**怕洩漏的不送、查不到的不亂講、真壞蛋抓得到**。這就是 §2-③「補充情報」那站在做的事。

> 數字的誠實態度：這些都是**小樣本**（幾筆到十幾筆），所以我們在報告裡都標清楚樣本數，
> **不誇大**成「絕對」。這是做研究該有的誠實。

## 8. 一頁總結（給沒時間的人）

1. **目標**：做一個自動幫資安警衛室做「第一線分流 + 初步整理」的 AI 小幫手。
2. **流程**：警報進來 → 分輕重 →（低風險走旁路快速結案）→ 查情報 → 調查真假 → 對照攻擊字典 → 寫處理建議 → AI 自我檢查 → **人類同意** → 出報告。
3. **怎麼接起來**：九站共用一張「表格」（IncidentState），每站只填自己那幾格。
4. **我們做的事**：把幾個**核心站**，分四個計畫（A 分類 / B 查情報+對手法 / C 判真假 / D 寫建議+自檢）接上真實能力；其餘站負責資料整理、分流、人類把關與報告。
5. **核心發現**：讓 AI 讀內容會變準（0.5→0.833），但也會被騙（這 3 筆注入 0/3→3/3）——所以**人類同意這道閘門不可或缺**。
6. **態度**：先寫規格、先寫測試、雙 AI 互審、跑真數據、第三方 AI 通篇校對；數字小樣本就誠實標註，不誇大。

## 附錄：看不懂也沒關係的小字典

| 看到這個詞 | 白話意思 |
|---|---|
| JSON 檔 | 電腦愛用、有固定格式的純文字檔（像填好的表格）。 |
| IOC | 警報裡「可疑的線索」：IP、網址、網域、檔案指紋等。 |
| BM25 | 一種搜尋方法，像搜尋引擎一樣「找最像的」。 |
| HTTP 401 | 網站回你一句：「你沒有通行證，不給看。」 |
| precision（精確率） | 它說「是攻擊」的那些裡面，有多少真的是攻擊（越高＝越少誤傷好人）。 |
| top-1 / top-3 | 只看「第一個答案」對不對 / 看「前三個答案」有沒有包含正解。 |
| LLM（大型語言模型） | 會讀字、會推理、會寫字的 AI（像 ChatGPT 那種）。 |
| 提示注入（prompt injection） | 壞人在文字裡偷塞指令，想騙 AI 聽他的話。 |
| 確定性 | 同樣的輸入每次跑都得到一樣的結果，不會亂變。 |
| 旁路（bypass） | 不走完整流程的「快速通道」（這裡給低風險警報用）。 |
